# CareerPilot AI — Security & Threat Modeling Specification

## 1. Security Architecture Principles
CareerPilot AI enforces strict enterprise-grade security, data privacy, and isolation guarantees across every tier of the application.

```
+-------------------------------------------------------------------------+
|                        SECURITY PERIMETER                               |
|  1. Strict User-Scoped Authorization Guards (Row & Vector Level)       |
|  2. SSRF Protection & Private IP Network Blocking                      |
|  3. Prompt Injection Defense (Data Boundaries & Strict Schemas)         |

+-------------------------------------------------------------------------+
```

## 2. Threat Vector Mitigation

### 2.1 Server-Side Request Forgery (SSRF) Defense
- **Risk**: Attackers providing URLs pointing to internal services (e.g. AWS metadata endpoint `169.254.169.254`, `localhost`, `127.0.0.1`, internal RFC 1918 subnets).
- **Control**: Implemented in [`SafeURLScraper`](file:///c:/Users/Lalith%20Sagar/OneDrive/Desktop/careerpilot-ai/backend/app/tools/url_scraper.py):
  - Resolves domain to IP before connection.
  - Rejects private, loopback, and link-local IP addresses.
  - Enforces `http`/`https` scheme validation.
  - Disallows internal redirects.

### 2.2 Cross-Tenant Vector & Data Isolation
- **Risk**: User A querying embeddings and inadvertently retrieving User B's resumes, documents, or interview notes.
- **Control**:
  - Every SQLAlchemy query filters strictly by `user_id == current_user.id`.
  - Every vector similarity search in [`RAGEngine`](file:///c:/Users/Lalith%20Sagar/OneDrive/Desktop/careerpilot-ai/backend/app/rag/engine.py) joins `DocumentChunk` and `Document` with mandatory `user_id` constraints.
  - Cross-user retrieval is mathematically impossible at both the database query and retrieval engine levels.

### 2.3 Prompt Injection Defense
- **Risk**: Malicious instructions embedded in uploaded resumes or scraped job descriptions attempting to override system behavior.
- **Control**:
  - Input text is framed explicitly as untrusted data with clear boundary tokens:
    ```
    --- BEGIN RESUME ---
    {untrusted_data}
    --- END RESUME ---
    ```
  - Outputs are enforced via strict Pydantic JSON schemas (`generate_structured`).
  - Evaluator & Critic Agent validates generated outputs against original verified facts before display.

### 2.4 Factual Integrity & Anti-Fabrication Guarantee
- **Risk**: AI hallucinating job experiences, degrees, metrics, or false qualifications.
- **Control**:
  - Candidate Profile extraction strictly copies only explicitly present facts.
  - Compatibility scores are calculated by deterministic mathematical formulas, not generated by LLM.
  - Resume bullet rewriting reframes existing achievements only and is verified by the Critic Agent.

### 2.5 Model Context Protocol (MCP) Tool Safeguards
- **Control**:
  - No arbitrary shell commands or raw SQL execution exposed.
  - All MCP tools are typed, validated, and user-scoped via token authentication.
  - Every MCP action is logged in `agent_runs`.

## 3. Authentication & Credential Storage
- Passwords hashed using `bcrypt` with individual salt generation.
- Stateless JWT access tokens signed with `HS256` and configurable expiration.
- Zero secrets committed to source control; configuration managed strictly via environment variables.
